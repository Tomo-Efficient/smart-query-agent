它做了什么

合成保险数仓 · 11 表 · 4 万保单 · 57 万行保费
01 / 语义层

33 张语义卡约束口径

指标、表、关系、术语四类卡片参与检索，把"保费到底含不含退保"写进 Prompt，而不是靠模型猜。

02 / 护栏

请求级 + SQL 级双层

生成前拦截危险意图，生成后做 AST 校验：单语句、只读、表白名单、敏感字段、自动 LIMIT。

03 / 权限

数据域在引擎层收口

账号绑定渠道范围，校验阶段把受控表改写成带过滤的子查询——越权的行根本查不到，不靠模型自觉。

04 / 交互

结果优先，过程可查

结论、指标、图/表切换；右侧轨迹逐步给出耗时、召回证据、SQL 与校验项，回答可复制、可重跑。

05 / 运营

审计、配额与多轮

每次提问留痕（谁、问了什么、什么 SQL、几行、多少毫秒）；追问会显式改写问题，不静默继承条件。

06 / 评测

164 题 + 四组消融

gold SQL 现场复算，分类准确率、失败归因、消融表与成本全部写进报告，一条命令重跑。

本地跑起来

Python 3.11+ · macOS / Linux

不需要模型 Key 也能跑：没配 Key 时走离线模板基线，链路、护栏、数据域、审计都完整，只是不能任意改写问法。

  1. 克隆与安装生成虚拟环境、装依赖。
  2. 生成数据合成数仓约 2 秒，写入 data/warehouse.duckdb。
  3. 启动打开 127.0.0.1:8000，用登录页的演示账号进入。
  4. 接真模型（可选）把 DEEPSEEK_API_KEY 写进 .env，顶栏会从"离线演示"变成"在线"。
# 1. 克隆与安装
git clone https://github.com/Tomo-Efficient/smart-query-agent.git
cd smart-query-agent
make setup

# 2. 生成合成数仓（约 2 秒）
make data

# 3. 启动
make serve
# → http://127.0.0.1:8000

# 4. 跑评测（可选）
make eval
为什么没有在线 Demo

它需要一个能跑 Python 的后端，而 GitHub Pages 只能托管静态文件

真版本要连 DuckDB、调模型、做 AST 校验和数据域注入，这些都发生在服务端。所以这里给的是截图与源码，不是可以点的按钮。

想现场看，克隆下来 make serve 即可；早期那版纯前端演示保留在 legacy-demo.html，用模拟数据，可以点但不会真的查库。

合成数据复现，数字与生产环境（85%+）分开口径，不混着说。
