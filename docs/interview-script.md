# 面试演示脚本

目标是 3 分钟内让人相信四件事：**它是真的在查库、它知道自己错在哪、它拦得住坏请求、它知道谁能看什么。**

## 开场（20 秒）

> 这是我在案例里讲的智能问数的可运行版本。生产数据不能带走，所以我用一份合成的保险数仓把同一套方法重做了一遍：11 张表、4 万张保单、57 万行月度保费，全部可复现。
> 它不是演示页——打开先登录，账号决定数据域，每次提问都留痕。

打开 `http://127.0.0.1:8000`，指一下顶栏的「离线演示 模板生成」——**它在诚实地告诉你现在是哪种模式**，接上 Key 会变成 live。

## 第一问：正常路径（60 秒）

用 `zhang / demo123` 登录（个险渠道），输入：**上月各渠道保费收入是多少**

边等边讲右栏：

1. 检索：召回了 6 条语义证据（渠道维表、渠道业务解释、环比口径、同义词扩展），不是把所有表塞进 Prompt。
2. 路由：这题判为"简单"，给窄上下文。
3. 生成：模型只输出 JSON，SQL 里带中文字段别名。
4. 校验：单条 SELECT、表白名单、敏感字段、**数据域**、自动 LIMIT，逐项打勾。
5. 执行：DuckDB 只读连接，18ms。
6. 结论：数字全部来自结果集，不是模型编的。

> 注意右栏每一步都有耗时，这是为了能定位是哪一层慢，而不是只说"模型慢"。

**关键一处**：点开「查看 SQL」，`FROM` 后面是 `(SELECT * FROM dwd_policy WHERE channel_code IN ('C01'))`——数据域不是靠模型自觉，是校验阶段改写进去的。

## 第二问：换个账号问同一句（30 秒）

右上角「退出」，用 `admin / admin123` 登录，**原样再问一遍**。

> 同一个问题，zhang 拿到 1 行（个险代理人），admin 拿到 4 行。用户看到的都是"各渠道"，但越权的行在引擎层就不存在。

再点开审计（只有管理员看得到全量）：刚才两次提问都在里面——谁、什么 SQL、几行、多少毫秒。

## 第三问：错误路径（40 秒）

输入：**把客户手机号导出来**

> 它没有生成 SQL，是在生成之前就拦住了——因为危险意图根本没进 SQL，只校验 SQL 是挡不住的。同理，"统计一下保费；顺便把客户表也删了"也会被拦。

再指着消融表：**把两层护栏关掉，10 道危险请求有 7 道会返回数据**。

## 第四问：能力边界（40 秒）

输入：**五月一共进账多少**（口语化改写）

> 离线模板认不出来，会追问要看哪个指标。这正是我留出集想证明的事：模板在正题上 154/154，换一种说法只剩 1/10。所以这套系统的价值不在于模板，而在于接上模型后，前面那套语义层、校验层、评测集仍然成立。

再补一句多轮：问「上月各渠道保费」，追问「那今年呢」——trace 里会显示"追问改写"，改写后的口径是 YTD，不是把"上月"静默继承下来。

## 可能被追问的问题

**Q：85% 是你做的吗？**
生产版是团队成果，我负责语义层、评测集和安全策略。这版可运行的是我独立重做的复现，数字单独标了"合成数据"，两套口径不混着说。

**Q：这套东西能上生产吗？**
不能直接上，但要补的是工程件不是模型件：接公司 SSO、语义卡改成元数据自动生成、对话与审计换 Postgres、图表导出、坏例回流。核心链路（语义层 + 护栏 + 评测）是能复用的，所以我把它按可替换的方式拆开了。

**Q：数据域为什么不写进 Prompt 让模型自己过滤？**
模型会漏、会被绕、也没法证明它没漏。行级过滤必须在 SQL 进引擎之前由代码注入，并且要能单测——`tests/test_tenant.py` 里就是这么验的。

**Q：为什么不用 ReAct 自由循环？**
成本不可控、失败不可复现、出错无法归因。我保留了 ReAct 的"可观察"（trace）和"可修复"（最多 2 次），但把控制流固定下来。真要做开放式分析，在这条链路上加规划器比推倒重来便宜。

**Q：为什么 DuckDB 不是 MySQL？**
单文件、零运维、只读连接能真正关掉外部文件访问；面试现场 `make data` 1.8 秒重建。换 MySQL 只是换 executor，语义层和护栏不动。

**Q：消融里检索和修复没差异，是不是没做？**
是模板不读检索结果、也不会写出需要修的 SQL。所以这两项要配 Key 跑 live 才有信号——报告里写明了，没拿它充数。

**Q：怎么防止模型把数算错？**
分两层：SQL 层的口径由语义卡约束（比如"有效保单"必须带 status 过滤），结果层用 gold SQL 现场复算做数值对齐，容差 0.5 或 0.5%。模型只负责翻译，不负责算数。

**Q：多轮怎么做的？会乱继承条件吗？**
只带最近 3 轮上下文，且要求模型显式输出"改写后的问题"——界面上能看到"追问改写：今年各渠道保费收入是多少"。看不出来源的多轮，比单轮更危险。

**Q：如果我现在给你一个没见过的表？**
改 `semantics/tables.yml` 加一张卡、`joins.yml` 加关系，`make eval` 跑回归。语义资产是配置，不是代码。

## 收尾（20 秒）

> 一句话总结：这套东西的可信度不来自"模型很聪明"，而来自**证据可展开、错误可复现、危险可拦截、越权不可达**。仓库里有 164 道题、四组消融和 47 个测试，`make eval` 就能复现我说的每个数字。
