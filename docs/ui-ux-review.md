# ChatBI 控制台 · UI/UX 设计评审

> 对象：`smart-query-agent` 的 Web 控制台（`web/index.html` 128 行、`web/style.css` ~700 行、`web/app.js` ~1000 行、`web/chart.js` ~190 行）
> 技术栈：FastAPI + 原生 ES（无框架、无构建、无第三方 UI 库），SVG 自绘图表
> 约束：**只改前端**。不动 `/api/*` 契约、不动 SQL 生成与执行、不动 `guard` 的权限/数据域判断、不动 `store` 的表结构
> 当前风格：黑白线框（1px 实线、0 圆角、无阴影、颜色不承担语义）

---

## 0. 一句话结论

现在的界面**已经把"可信"讲清楚了**（能追 SQL、能看校验、能拦住危险请求），但**还没把"好用"做出来**：

> 信息层级靠字重和灰度硬撑；状态靠一枚小标签；图表和表格只能二选一；空/错/权限不足共用一套壳。

这一版不改气质，只改三件事：**顺序、对比、可恢复**。目标是让人在 3 秒内回答四个问题——问什么、结果是什么、数据从哪来、下一步问什么。

## 1. 现状诊断

### 1.1 事实（对着代码核对过）

| 维度 | 现状 |
|---|---|
| 布局 | 三栏：左 236px 历史 / 中间 `1fr` / 右 380px 轨迹；≤900px 时左栏与轨迹变成覆盖层 |
| 字号 | **12 种**：10.5 / 11 / 11.5 / 12 / 12.5 / 13 / 13.5 / 14 / 14.5 / 15 / 21 / 26 |
| 灰度 | 4 级：`#111` / `#333` / `#6b6b6b` / `#9a9a9a` |
| 状态 | 5 类：`已完成 / 需要澄清 / 已拦截 / 执行失败 / 运行中`（另有"已停止"），视觉上只有"实线框 / 虚线框 / 黑底反白"三种区分 |
| 图表 | `rows ≥ 3 且 ≤ 24` 才画；月度序列→折线，其余→条形；**有图时表格默认折叠**，没有"图/表"切换控件 |
| 结果 | 结论 → KPI → 图 → 折叠表 → 口径 chips → 折叠（SQL/校验）→ meta 行 → 接着问 |
| 加载 | 顶部状态条回显当前步骤 + 回答区一行灰字呼吸；步骤有耗时条与最慢步骤 |
| 空态 | 标题 + 4 条示例；手机上额外显示"最近问过" |
| 可访问性 | 有 `:focus-visible`、`role=dialog`、`aria-hidden`、`aria-live`；但无焦点陷阱、无跳转链接、`#9a9a9a` 对比度不达标 |

### 1.2 问题（按影响排序）

**P0 · 伤"一眼看懂"**

1. **12 种字号 = 没有字号阶梯。** 10.5 与 11、12 与 12.5 的差别肉眼不可辨，结果是所有文字看起来"差不多重要"，用户只能逐行读。
2. **`--faint: #9a9a9a` 对白底 2.85:1，不达 WCAG AA（4.5:1）**，偏偏它用在 10.5–11px 的 meta、时间、提示上——最需要看清的地方最看不清。
3. **口径 chips 与"接着问" chips 长得一模一样**（都是 1px 线框小胶囊）。一个是"解释"，一个是"动作"，语义完全不同，却共用一种形状，用户会先读解释、错过动作。
4. **状态只是文字。** `已完成` 与 `已拦截` 在结构上完全同构（同一种边框标签），差异要靠读字；没有图标、没有位置差、没有形状差。

**P1 · 伤"能继续/能恢复"**

5. **图与表是互斥的，不是可切换的。** 有图就把表折起来，想核对数字得展开折叠；想要图又不想要表时没有选择。没有"图/表"分段控件。
6. **`row_count = 0` 没有专门状态。** `status = ok` 且零行时，界面就只剩一句结论，没有任何"为什么空 / 换什么问"的出口。
7. **"权限不足"与"安全拦截"共用 blocked 卡。** 数据域拒绝（"表不支持按渠道过滤"）和"你要删库"用的是同一张红框，语气和后续动作都不同。
8. **澄清态不可点。** 澄清文案是纯文本（"你想看哪个指标…"），用户得自己重新打一遍；应该是 3–4 个可点选项。
9. **追问建议无排序、无上下文标签。** 固定三条启发式，不区分"顺着看"和"换个维度"。

**P2 · 伤"专业感"**

10. **加载只有文字。** 3 秒的首字延迟里，回答区是一行灰字；没有骨架、没有进度比例，右栏的步骤条反而比主区更有信息量。
11. **移动端入口隐藏。** 语义资产/审计在左栏 footer，手机上要先开历史抽屉才能进；顶栏只剩「历史 / 轨迹 / 用户」。
12. **没有密度与暗色。** 宽屏下 236/380 固定，中间内容一多就挤；演示场景没有深色版本。

## 2. 两个视觉方向

### 方向 A ·「Paper & Ink」克制的编辑感（推荐）

保留现在的黑白线框骨架，把它从"线框"升级成"出版物"：**用留白和字阶建立层级，用一条墨蓝只标记"可交互"**。

- 底色：纸白 `#FFFFFF`，卡片区 `#FAFAFA`，悬浮区 `#F4F4F5`
- 文字：墨黑 `#0E0F11`（正文）→ `#35373B`（次级）→ `#5F6368`（说明）→ `#7A7E85`（meta，4.6:1）
- 线：`#E7E7E9`（常规）/ `#0E0F11`（强调 1px，只用于"当前项"与"结论分隔"）
- 唯一功能色：`#1D4ED8`，只出现在**焦点环、链接 hover、图表选中点**，不填充任何块
- 状态靠形状 + 位置：成功=细线+✓、澄清=虚线+?、拦截=左侧 3px 黑竖条、失败=斜纹底
- 数字用 tabular-nums，SQL 用等宽

**为什么推荐**：它延续了你现在的气质（简历里那张黑白稿），改动是"精度"不是"换皮"；黑白对打印、投屏、README 截图都安全；而且**它逼着信息层级靠排版解决**，不靠颜色堆。

### 方向 B ·「Instrument」深色仪表盘

深色 `#0B0C0E` + 网格线 + 等宽数字 + 一个琥珀色信号色，适合大屏演示和"科技感"叙事。

- 优点：第一眼冲击力强，"数据产品"的氛围直接
- 代价：长段中文在深色下阅读疲劳；README/简历/打印全部要重做对比；图表配色、状态色、表格斑马纹都要重调；和现有"纸感"作品集风格断裂

**结论：走 A。** B 作为**可选主题**后置——只要把颜色全部收进 CSS 变量（现状已经做到了 80%），B 就是一次变量替换，不是重构。

## 3. 设计 Tokens

### 3.1 颜色

| Token | 值 | 用途 | 对比度 |
|---|---|---|---|
| `--ink-900` | `#0E0F11` | 正文、标题、KPI 数字 | 18.6:1 |
| `--ink-700` | `#35373B` | 次级正文、表格首列 | 12.1:1 |
| `--ink-500` | `#5F6368` | 说明文字、步骤 detail | 5.9:1 |
| `--ink-400` | `#7A7E85` | meta、时间戳、占位 | 4.6:1 ✅ |
| `--line-200` | `#E7E7E9` | 常规分隔线、卡片边 | — |
| `--line-300` | `#D6D6D9` | 输入框、折叠头 | — |
| `--line-900` | `#0E0F11` | 强调边（当前项、结论分隔） | — |
| `--bg` | `#FFFFFF` | 页面底 | — |
| `--surface-50` | `#FAFAFA` | 表格头、条形轨道 | — |
| `--surface-100` | `#F4F4F5` | hover 行、选中项 | — |
| `--focus` | `#1D4ED8` | 焦点环、链接、图表选中 | 5.2:1 |
| `--danger` | `#B42318` | 失败图标/左边框（**不填充**） | 5.9:1 |
| `--warn` | `#B54708` | 澄清图标/左边框（**不填充**） | 5.5:1 |
| `--ok` | `#067647` | 成功图标（**可不使用**，见风险 R3） | 5.2:1 |

> 功能色只允许出现在 **图标、1–3px 边框、下划线**；任何大面积填充仍然是黑白。

### 3.2 字体与字号

| Token | 值 | 用途 |
|---|---|---|
| `--fs-11` | 11px / 1.5 | 分组标签（`letter-spacing:.08em`）、KPI 标签 |
| `--fs-12` | 12px / 1.6 | meta、时间、折叠计数 |
| `--fs-13` | 13px / 1.6 | 次级 UI（按钮、chips、表格） |
| `--fs-14` | 14px / 1.7 | 默认 UI |
| `--fs-15` | 15px / 1.75 | **回答正文** |
| `--fs-16` | 16px / 1.5 | 小节标题 |
| `--fs-24` | 24px / 1.25 | KPI 大数 |
| `--fs-28` | 28px / 1.2 | 首屏标题 |
| `--mono` | ui-monospace… | SQL、数字对齐 |

**规则**：从 12 种收敛到 8 种；10.5/11.5/12.5/13.5/14.5 全部并入相邻档；数据一律 `font-variant-numeric: tabular-nums`。

### 3.3 间距 / 形状 / 动效

| Token | 值 | 用途 |
|---|---|---|
| `--sp-1…8` | 4 / 8 / 12 / 16 / 24 / 32 / 48 / 64 | 全站唯一间距体系 |
| `--radius` | `0`（保留） | 设计意图：纸与线 |
| `--border` | `1px solid var(--line-200)` | 默认 |
| `--border-strong` | `1px solid var(--line-900)` | 当前项 |
| `--focus-ring` | `0 0 0 2px #fff, 0 0 0 4px var(--focus)` | 键盘焦点 |
| `--dur-fast` | `120ms` | hover、按钮 |
| `--dur` | `180ms` | 折叠、切换 |
| `--dur-slow` | `240ms` | 抽屉、面板 |
| `--ease` | `cubic-bezier(.2,.6,.2,1)` | 统一 |
| 层级 | `10` 顶栏 / `20` 吸顶 / `40` 下拉 / `60` 遮罩 / `70` 抽屉 / `90` 指令面板 | z-index 标尺 |

### 3.4 内容宽度

- 回答正文：`max-width: 68ch`（当前 780px 在 15px 下约 52 个汉字/行，偏宽）
- 图表：与正文同宽，高度固定 168–200
- 表格：不受 68ch 限制，占满内容区，首列 sticky

## 4. 关键区域改造清单

> 每区给：现状 → 改法 → 验收。全部在前端内完成。

### 4.1 对话主界面（三栏）

| 项 | 内容 |
|---|---|
| 现状 | 236 / 1fr / 380 固定；右栏一直占位 |
| 改法 | ① 中间回答区 `max-width: 68ch` 居中，右侧留白吸收宽屏；② 右栏可在 380/320 之间随视口收缩；③ 回答之间用 `--sp-8`（32px）+ 细分隔线分组，用户问题靠右、回答靠左的节奏保留 |
| 验收 | 1440 宽下正文行长 ≤ 40 汉字；缩到 1024 不出现横向滚动 |

### 4.2 输入区

| 项 | 内容 |
|---|---|
| 现状 | 单行 textarea + 发送；运行中变"停止"；底部提示 `只读 · 上限 200 行 · ⌘K 指令` |
| 改法 | ① 高度随内容 1–5 行，超过滚动；② 运行中在输入框左侧显示**阶段点**（检索/生成/校验/执行），而不是只有顶部一条；③ 发送按钮在空输入时 disable（视觉 30% 透明）；④ 保留 `Enter 发送 / Shift+Enter 换行`，但只在首次聚焦时显示，输入后淡出 |
| 验收 | 长问题不撑破布局；运行中一眼看到"卡在哪一步"；空输入不会提交 |

### 4.3 结果卡片

| 项 | 内容 |
|---|---|
| 现状 | 结论 → KPI → 图 → 折叠表 → 口径 → 折叠 → meta → 接着问 |
| 改法 | ① 结论 15px/1.75，最多 3 行，超出折叠"展开"；② KPI 最多 3 个，超出改为表格第一行加粗；③ 口径 chips 与实际数字之间加 4px 间距并降为 12px/`--ink-500`；④ meta 行从 8 段压到 4 段（耗时、行数、模式、数据域），其余进 tooltip |
| 验收 | 视线顺序：结论 → 数字 → 图 → 想深究才看口径；单屏能看到结论与图 |

### 4.4 图表 / 表格切换

| 项 | 内容 |
|---|---|
| 现状 | 有图则表格折叠，二选一 |
| 改法 | 结果区顶部加 **分段控件** `图 | 表`（无图时只有"表"），默认"图"；切换状态记在 `sessionStorage`，同一会话内保持一致；"表"视图保留排序/复制；图下方不再重复折叠表 |
| 验收 | 一键切换，不刷新页面、不重新请求；偏好被记住 |

### 4.5 SQL / 口径 / 来源折叠

| 项 | 内容 |
|---|---|
| 现状 | 两个并排 details（SQL / 校验项）+ 口径 chips 裸露 |
| 改法 | ① 合并为一行 **"依据"**：`口径 3 · 校验 5 · SQL`，点开是同一块；② SQL 折叠里加"复制/下载 .sql"；③ 口径改为"名词 + 一句话"，hover 显示完整卡（来自 `/api/semantics` 已有数据，不新增接口） |
| 验收 | 默认不干扰；需要时两次点击内看到 SQL 与校验 |

### 4.6 加载阶段反馈

| 项 | 内容 |
|---|---|
| 现状 | 顶部状态条 + 一行灰字 + 右栏步骤 |
| 改法 | ① 回答区加**三行骨架**（结论行、KPI 行、图区），随步骤逐步"点亮"；② 阶段标签用"正在生成 SQL · 1.8s"；③ 超过 8s 显示"还在跑，可 Esc 停止"；④ 停止后保留骨架并替换为"已停止，可重跑" |
| 验收 | 首字延迟期间页面不"空"；任何时刻知道进度与退出方式 |

### 4.7 空 / 失败 / 权限不足 / 歧义

| 状态 | 现状 | 改法 |
|---|---|---|
| 无数据（0 行） | 只有一句结论 | 专属空态：`没有匹配的数据` + 两条可点建议（放宽时间、去掉筛选）+ "看看最近一次有数据的月份"|
| 失败 | 通用 error 卡 | 显示**可复制的错误摘要** + 三个动作：重试、换问法（把原问题塞回输入框）、看 SQL |
| 权限不足 | 与安全拦截同卡 | 单独样式：`这个范围你没有权限` + 显示当前数据域 + "切换到有权限的维度"建议；**不出现"拦截"字样** |
| 歧义 | 纯文本追问 | 追问卡带 **2–4 个可点选项**（如"按渠道 / 按险种 / 整体"），点选即提交，不再手打 |
| 已拦截 | 红框 × | 保留，但补一句"这不是系统故障"的定级说明 + 示例安全问法 |

### 4.8 追问建议

| 项 | 内容 |
|---|---|
| 现状 | 固定 3 条启发式，无排序 |
| 改法 | 分两组：`顺着看`（趋势 / 同期 / 排名）与`换个维度`（按险种 / 按渠道 / 按机构）；按当前结果列名排序，最多 3 条 + "更多"；点击后把新问题回填输入框再提交（可编辑） |
| 验收 | 建议与当前结果强相关；点一下就能继续，不用重打 |

### 4.9 移动端

| 项 | 内容 |
|---|---|
| 现状 | 左栏/轨迹全屏覆盖；顶栏仅历史/轨迹/用户 |
| 改法 | ① 历史改**底部抽屉**（可从底部上滑、带把手），符合单手操作；② 轨迹改**底部半屏**，默认 60% 高；③ 图表用 360 宽视口（已做），表格横向滚动 + 首列 sticky；④ 输入区固定底部并处理 `safe-area-inset`；⑤ 顶栏把"语义资产/审计"收进 `⋯` 菜单，不再依赖左栏 footer |
| 验收 | 单手可达；横滑表格不带动页面；抽屉可下拉关闭 |

### 4.10 侧栏与顶栏

| 项 | 内容 |
|---|---|
| 现状 | 左栏列表平铺；顶栏 6 个控件 |
| 改法 | ① 会话按`今天 / 昨天 / 更早`分组；② hover 才出现删除（保留），补"重命名"可选；③ 顶栏收到 4 个：品牌、数据截止、模式、用户；`轨迹` 与 `语义资产` 移入 ⌘K 与侧栏 footer |
| 验收 | 顶栏不拥挤；会话超过 10 条仍可扫读 |

## 5. 优先级与工作量

| 优先级 | 内容 | 预估 |
|---|---|---|
| **P0** | 字号/灰度 token 收敛（含 4.6:1 修复）、状态形状化、结果卡层级与 68ch、图/表分段切换、四种状态卡（空/失败/权限/歧义） | 2.5 天 |
| **P1** | 加载骨架与阶段标签、追问分组与回填、依据折叠合并、会话分组、移动端底部抽屉 | 2 天 |
| **P2** | 暗色主题、密度切换、动效细化、表格排序 | 1.5 天 |

建议顺序：**P0 的 token 与状态 → 结果卡 → 图/表切换 → 状态卡 → P1**。每步都能独立上线，不需要一次性重构。

## 6. 风险点

| 风险 | 影响 | 规避 |
|---|---|---|
| R1 token 迁移视觉回归 | 全局样式变动，局部错位 | 先**新增**变量并保留旧别名，逐组件替换；每个 PR 附 1440/1024/390 三张截图对比 |
| R2 图/表切换需要前端状态 | 历史回放时状态丢失 | 用 `sessionStorage` 记偏好 + `data-*` 挂到消息节点，历史回放沿用当前偏好 |
| R3 功能色与"只用黑白"冲突 | 破坏既定风格 | 功能色只用于图标/边框，且可由 `--accent: none` 一键关掉；先做一版灰度形状化，再决定是否引入 |
| R4 澄清选项化需要"可选项"来源 | 后端只返回一段文本 | **不改接口**：前端从文本里匹配"保费/件数/退保率/赔付率"等已知词生成选项；匹配不到就退回纯文本 |
| R5 移动端抽屉与焦点管理 | 键盘/读屏体验回退 | 统一 `inert` + 焦点陷阱 + `Esc` 关闭；底部抽屉加 `aria-modal` |
| R6 图表推断是启发式 | 选错值列（如把"件数"当"率"） | 现有 `pickValueCol` 已按"率先行"排序；补 6 条回归用例（率/金额/件数/月份/空标签/单行） |
| R7 68ch 与三栏冲突 | 宽屏留白过多显得空 | 让右栏吸收多余宽度（`minmax(320px, 380px)`），中间居中而不是拉伸 |

## 7. 验收标准对照

| 你的验收标准 | 落点 | 判定方式 |
